# AAC Studio v0.4.0

A WILLIAM MCADA PRODUCT. Offline HTML and hosted assessment workspace using AAC Blueprint 4.8.0 and exchange contract v4. Grades 5–7, Forms 1–8, fifteen one-point items per form. See `docs/releases/0.4-release.md` for repair decisions and actual verification results.

This repository is the canonical source and release record for AAC Studio. The official v0.4 baseline includes the complete recoverable source snapshot `AAC_Studio_v0.4_verified_source.zip`, the exact verified portable release `AAC_Studio_v0.4.html`, the accepted repair specification, and the release evidence. The earlier `AAC_Studio_v0.3.html` baseline remains preserved for recovery and comparison.

## Daily workflow

1. Select an unlocked form in Dashboard.
2. Download its generation packet and attach it to an AI conversation. The file includes all 15 assignments, 30 cyclic neighboring structures, paired grades, the permanent rules, and a JSON response skeleton.
3. Import the completed JSON or TXT result. Resolve item issues, inspect the questions and figures, and accept each item.
4. Complete the whole-form review, finalize the assessment, and export its five-part Word package. Student fractions use native editable Word equations. Print / Save PDF opens the browser print flow.

Backups & history downloads the full blueprint plus saved assessment state. Restoring a backup cannot change or remove an already finalized form. Every successful write records a revision. Older revisions are available through Load earlier revisions.

## Validation boundaries

Shared offline/server validators enforce assigned fingerprints, objective response shapes, MCQ counts, visual presence/absence, supported math syntax, identifiers, DOK allocations, comparison caps, cluster allocations, claim coverage, and canonical cyclic/paired exclusions. Intrinsic variation categories are descriptive, not quota evidence. Difficulty is a provisional task target, not a position-derived or calibrated label. New imports invalidate item reviews. Editing an accepted item invalidates its review and all whole-form checks.

Canonical core checks cannot prove that generated prose realizes the intended mathematical action. The teacher must check the actual action and given/unknown relationship, answer correctness, content boundaries, visual semantics, workload, redundancy, and ELL accessibility before finalization. A matching fingerprint alone does not establish mathematical validity. Numeric answers are checked for shape; the app is not an algebra grader.

Math supports explicit inline delimiters and a deliberately bounded grammar: fractions, roots, powers, subscripts, common operators, and elementary geometry symbols. Unsupported notation is flagged. Figures use safe SVG, embedded PNG/JPEG, or appropriate native tables. Word export rasterizes diagrams but preserves student equations as OMML. Document dimensions and tables were rendered and visually checked with an isolated export fixture; no fixture questions ship as assessment content.

## Persistence and implementation

The application uses a D1 revision pointer and event history with immutable R2 snapshots. Optimistic concurrency rejects conflicting saves. A failed write keeps the prior state. The deployment starts private and is intended as the owner's single AAC workspace.

The source uses the managed Sites Vinext starter, React, TypeScript, and shadcn primitives. JSZip 3.10.1 was reused from the available TestForge v1.4 package under its MIT/GPL dual license; its original license header is retained in vendor/jszip.cjs. The AAC rule engine and native Word equation exporter are specific to this app. No AI API key is required.

Run `pnpm install`, `pnpm exec tsc --noEmit`, `node scripts/test-aac.mjs`, and `pnpm build` in a supported development environment. Production schema changes are generated with `pnpm db:generate`; committed Drizzle migrations are schema-only. The authoritative migration input is AAC_BLUEPRINT_v4.4.xlsx. The migration script records its SHA-256 provenance in lib/seed.json.

Automated tests cover packet integrity, malformed imports, response rules, cyclic exclusions, prohibited/required visuals, unsafe SVG, identifier collisions, review invalidation, locked-state protection, backup roundtrips, stale packets, save races, storage failures, and native math markup. Browser interaction testing and live WebMCP validation were unavailable in the permitted build workflow. Three optional WebMCP actions are feature-detected for reading status, opening a form, and exporting a packet; they do not finalize assessments.

## Single-file offline edition

Run `node scripts/build-offline.mjs` to produce `outputs/AAC_Studio.html`. The file embeds the existing AAC interface, all blueprint data, fonts provided by the system, styling, scripts, validators, and Word exporter. It has no server or CDN dependencies.

Open the HTML directly in Chrome or Edge. Work saves locally in IndexedDB; figures are deduplicated across saved revisions. Save HTML copy embeds the entire current workspace in a new standalone file with a new local workspace identity. JSON backups remain compatible with the hosted edition. A copied file carries current work; detailed revision history remains in the browser where it was recorded. This edition does not synchronize automatically with the hosted site.

The offline build does not change or republish the hosted edition. The test in tests/offline.tsx uses fake-indexeddb 6.0.0 as an isolated test-only dependency to check storage, history, concurrent writes, locked forms, safe embedded JSON, and a saved HTML roundtrip. The generated document's inline JavaScript is syntax-checked and its assets are checked for external dependencies. No browser interaction test was run in this build workflow.
